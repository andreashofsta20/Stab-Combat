# Source, resource lifetime and remote audit

Reviewed on 4 October 2026. The scope is the Rojo `src` tree: the complete source inventory is in [SOURCE_AUDIT_INVENTORY.json](SOURCE_AUDIT_INVENTORY.json), regenerated by `scripts/audit-source.ps1`. Counts identify review targets; a connection count alone is not evidence of a leak. Packaged dependencies and scripts/assets that exist only in the live Studio place are outside this source review.

## Changes made

- **First-person menus:** `MenuCamera` watches menu visibility and GUI replacement through events. For a living player's native camera, a menu temporarily switches locked first person to Classic and pushes a fully zoomed camera outward for one native update. Zoom limits then return to their prior values. Closing all menus restores the saved mode. A native modal button and shared cursor visibility ownership keep the menu cursor usable. This supports the menus under `Main.Frames`, the emote menu and the tutorial, including trade, case spinner and round results. Scriptable, foreign-subject, dead and VR views retain their camera state. There is no permanent render loop or camera CFrame modification.
- **Player startup:** `OnJoined` now disconnects the old humanoid death hook on removal/respawn, releases player hooks on departure or failed hydration, and bounds its humanoid wait. Delayed setup cannot bind to a departed player.
- **Overheads:** character removal now destroys the old overhead and releases VIP, settings, streak and health listeners even when the old character remains allocated. Departure releases CharacterAdded/CharacterRemoving hooks. Health tween replacement destroys the old tween, and delayed setup rejects stale characters.
- **Hitboxes:** removed a death listener with an empty callback. CharacterRemoving now disconnects the retained child-removal hook and retires that character's hitbox. Animator observation also guards duplicate startup registration.
- **Offline profile requests:** retained the one-second player cooldown and one outstanding request per player; added a server-wide burst of four reads, refill of one per second, at most two concurrent offline reads, and one read per offline target. No spam queue is allocated. Successful offline responses use a maximum 64-entry, 30-second cache; online profiles bypass it. IDs must be positive finite integers within the safe integer range, and the requester must have loaded data.
- **Leaderboards:** name caching is limited to 256 entries. Writes for one player are serialized with one pending latest snapshot, including departure's final values. Listeners disconnect before departure writes can yield. Failed store writes still retry through the normal refresh cycle.
- **Other repeated work:** removed a three-second task from the legacy RequestKnife remote that performed no action. Zone warnings now send on changes rather than every damage tick. Trade timeout checks inspect each session once instead of once per participant. Quest startup rejects duplicate observer registration.
- **Remote hardening:** added a single outstanding admin command per authorized player so yielding backend commands cannot accumulate. Inventory-wipe debounce only records connected targets and clears them on departure. Keybind strings and setting names are length-bounded before parsing/lookup.

A malformed remote invocation generally fails that callback; it does not automatically terminate every server script. The availability risks here are repeated expensive work, suspended handlers, reply amplification and incorrect state mutation. Existing combat/trading/purchase defenses were retained; the changes above close specific remaining resource and admission gaps. This review does not establish that no exploit is possible.

## Verification and live checks

`scripts/test-performance-polish.ps1` runs every regression runner. Added checks exercise malformed IDs, concurrent random offline profile requests, cache/live-profile behavior, slow admin commands, delayed leaderboard writes, zone warning repetition, 30 respawn cycles, cursor owner ordering, overlapping/disabled menus, deferred camera property signals and teardown. Compilation and a Rojo build check source integration.

Latest verification on 4 October 2026: all 19 suites passed (851 checks); all 212 source/test files compiled; the Rojo build and whitespace check passed. The source inventory still covers 192 files and 25 client-to-server handlers. The weapon/spectate follow-up adds a bounded local bullet-mark pool, event-driven spectator stats/roster, automatic GUI rebinding and explicit listener/task cleanup; the server's new impact-surface field comes from its own raycast and accepts no new client hit data.

The tests use deterministic Roblox service fixtures. Native input/render behavior, actual FPS, Luau heap retention over long server sessions and live-place-only code still require Studio/client playtesting. Start a fresh session after syncing the source; open each menu from locked first person and manual maximum zoom, then verify scrolling/cursor use and restoration. In a private test server, repeat respawns and player departures and inspect LuaHeap, InstanceCount and PlaceScriptMemory after garbage collection. Use the MicroProfiler to compare equip and gameplay frame times; no numerical FPS improvement is claimed from static review.

## Primary research

- [Roblox client/server boundary guidance](https://create.roblox.com/docs/scripting/security/client-server-boundary): type/structure/value checks, finite numbers, permissions and server-enforced rate limits.
- [Roblox performance guidance](https://create.roblox.com/docs/performance-optimization/improve): retained player connections, table cleanup, unnecessary frame work and excessive remote traffic.
- [GuiButton.Modal](https://create.roblox.com/docs/reference/engine/classes/GuiButton/Modal) and [native camera modes](https://create.roblox.com/docs/workspace/camera): release the cursor with native GUI support and temporarily use Classic to allow zooming.
- [Finding performance issues](https://create.roblox.com/docs/performance-optimization/identify): Developer Console and MicroProfiler measurements for native verification.
